### Summary

The paper asks whether autoregressive TTS models' well-documented failure to correctly render repeated phrases ("say six hundred sixty-six thousand...") is driven by input *length* or by *repetition/periodicity* per se. Using a parametric "repetition ladder" (180 items, target word repeated k = 1–32 times, each paired with a length-matched control in which the repeated token is replaced by distinct fillers), the authors measure exact-count accuracy across six TTS checkpoints spanning three architectures (Llasa 1B/3B/8B, Qwen3-TTS 0.6B/1.7B, XTTS-v2), plus two non-autoregressive baselines (VITS, F5-TTS). The headline result is a large, robust gap in exact-count accuracy between repeated and length-matched control items (18.2% vs 94.3% at k≥6), which the authors show survives greedy decoding, repetition-penalty sweeps, exclusion-rule ablations, and re-scoring by four different recognisers (ruling out ASR/judge artifacts). A secondary "period ladder" partially dissociates periodic ordering from verbatim identity. Finally, the authors formally state a Lean-4-verified mechanistic hypothesis (state-space contraction implying a Lipschitz-readout bound on countable repetitions) and empirically refute its premise across five checkpoints, concluding the failure's true mechanism remains open.

### Major concerns

1. **Issue** — The manipulation confounds "periodicity" with training-distribution naturalness (how out-of-distribution the local word n-gram is), and this confound is never fully separated.
   **Where** — Section 2 (Stimuli: control replaces "the repeated token" with distinct fillers); Section 5, "What the design does not separate" ("Periodicity is not separated from training-set frequency, though the obvious form of it predicts the wrong arm... under an independent LM the control is the less probable text in 87% of pairs. Text likelihood is not corpus frequency, so it is weakened, not closed.").
   **Why it matters** — A sentence with a word repeated 6–32 times consecutively ("cat cat cat cat cat cat") is an extremely atypical local structure for any corpus a TTS model was trained on, independent of whether the mechanism is "periodicity" in the sense the Lean-4 contraction argument formalizes. The authors' own mitigation — checking that repeated text is not simply *less probable* under an independent LM — tests corpus-frequency at the whole-sequence level, not distributional naturalness of extreme immediate self-repetition, which is exactly the kind of local anomaly transformer induction heads and codec-token duration models are least trained to handle. Because the entire mechanistic apparatus of Section 4 (attention flattening → boundary-map contraction) is *specific* to periodicity as a computational structure, if the true driver is instead "OOD local repetition triggers degenerate decoding," the paper's title claim ("Repetition, Not Length") is directionally right but its causal specificity ("periodicity" as the operative variable, as opposed to unfamiliarity) is not established by this design.
   **What would address it** — Add conditions that cross periodicity with naturalness independently: (a) naturally-occurring repeated words in fluent text (e.g., "very very tired," "no no no") that are periodic but in-distribution; (b) non-periodic but equally OOD text (e.g., rare non-repeating token sequences matched for LM perplexity to the repeated condition). This would let the paper distinguish "periodicity causes the failure" from "distributional novelty of extreme local repetition causes the failure."

2. **Issue** — The control stimuli are not clean controls at high k: the filler pool is "cycled above k=8," making the control itself period-8 exactly where the deficit is largest.
   **Where** — Section 2 (Stimuli); Section 3.1 ("Above k = 8 the cycled control is itself period-8, so that contrast is p = 1 against p = 8 rather than against aperiodic text. Never-cycled fillers throughout remove it: the gap is 69.6 by checkpoint and 67.6 by family against 76.7 and 75.4 cycled, and we quote the smaller...").
   **Why it matters** — The paper's most-quoted numbers (18.2% vs 94.3%, Table 1, Fig. 1a) are drawn from the design that uses this cycled pool by default; the cleaner never-cycled comparison is reported only as a secondary check with a ~9-point smaller gap. This is a genuine design flaw baked into the primary stimulus set (only 8 fillers per template), not merely a robustness check — a reader has to reconstruct which of two different "control" definitions underlies which number in the paper.
   **What would address it** — Make the never-cycled comparison primary throughout (Table 1, Fig. 1, abstract), or expand the filler pool so no cycling occurs within the tested k range (up to 32).

3. **Issue** — The mixed-effects analysis models architecture and checkpoint as random effects but not carrier/template, despite the underlying stimulus set being only 180 items; several headline n's (n=1539 for the period ladder, n=525 for the k≥6 comparison) are generated by replicating those same items across seeds and checkpoints.
   **Where** — Section 3.1 ("A mixed-effects linear probability model with architecture as a random effect and checkpoint nested inside it puts the gap at 76.4 points, and all six interval constructions exclude zero..."); Fig. 1 caption; S6/S11 (referenced, not shown).
   **Why it matters** — If item/template variance isn't modeled as a random effect, standard errors and CIs computed treating each generation as an independent observation risk being narrower than warranted, which would make the reported "all six interval constructions exclude zero" and "widest being [63.2, 89.2]" appear more decisive than the true precision supports.
   **What would address it** — Report a model with carrier/template as a crossed random effect (in addition to checkpoint/architecture) and show whether the interval widens materially.

4. **Issue** — The experiments designed to adjudicate specific mechanistic sub-questions (does periodic *ordering* itself carry the effect, versus verbatim identity; does the count survive in state versus fail at readout) run on very small, sometimes single-cell samples, yet are used to support architecture-specific and general mechanistic conclusions.
   **Where** — Section 3.1, "Does the ordering carry it?" (shuffle test only interpretable at p=4, since "at p = 2 the unique zero-adjacency arrangement is the alternation, so any shuffle reintroduces adjacent repeats," and the resulting split — "two checkpoints gaining 17.8 points against XTTS-v2 losing 30.0" — is reported with no stated n); Section 2 (Whisper-vs-CTC ground-truth audit at n=12 over 6 donors, and n=24); Section 5, rank-1 patch experiment ("on Llasa-8B it is never detectable, bounding only 36% at n=18").
   **Why it matters** — These are precisely the experiments meant to distinguish competing causal accounts (state-erasure vs. readout failure; ordering vs. identity), and the paper states firm-sounding conclusions from them ("Periodic ordering drives Qwen, not the panel"; "It is registered but carries nothing") that a single small-n contrast, run once, cannot really support.
   **What would address it** — Report per-comparison n's explicitly next to each claim, replicate the shuffle test and rank-1 patch experiment with substantially larger samples before stating architecture-general causal conclusions.

5. **Issue** — The k≥6 threshold that anchors the paper's headline statistics was chosen after inspecting where the two curves diverge.
   **Where** — Section 3.2 ("The k ≥ 6 threshold was chosen after seeing where the arms diverge, which is why the abstract gives the unconditioned figure too... and the specification curve varies it.").
   **Why it matters** — This is disclosed, which is commendable, but disclosure does not remove the statistical concern: a data-dependent cutoff is a classic degree of freedom that inflates the apparent effect size at the chosen threshold, and it is exactly this threshold (not the unconditioned k=1 figure) that produces the paper's most quotable numbers (18.2% vs 94.3%, Table 1).
   **What would address it** — Either lead with the unconditioned k=1–32 curve as the primary statistic, or pre-register the threshold in a held-out replication sample and report that as confirmatory.

6. **Issue** — The paper's stated inferential philosophy is inconsistent: it explicitly declines multiple-comparison correction across 420 specification-curve variants ("these are not independent tests and we correct across none of them... our claims rest on effect sizes, not p-values") yet elsewhere reports a specific p-value for a single exploratory contrast without correction.
   **Where** — Section 3.1 (specification curve passage); Section 3.1, shuffle test ("Shuffling each item's own multiset recovers 0.006 of a 17.7-point deficit, excluding the pre-committed confirmation band (P =0.010)").
   **Why it matters** — Mixing an avowedly correction-free, effect-size-only framework with an isolated significance-style p-value for one of many post-hoc contrasts makes it unclear what standard of evidence the paper is actually holding itself to, and leaves that specific P=0.010 without any stated correction for the many other tests run in the same section.
   **What would address it** — Adopt one consistent framework throughout (effect-size-with-interval or correction-adjusted significance testing), and if p-values are reported anywhere, state the correction applied or explicitly justify why none was needed for that particular pre-registered test.

- The public repository is described as "https://github.com/lab260ru/icassp_antispoofing (name predates this study)" — a mismatched repo name for the study's content is a minor but real provenance/reproducibility wrinkle worth resolving before camera-ready.

- Self-citations to companion/contemporaneous work by the same author group ([7], [13]) carry arXiv IDs dated in the near future relative to typical review timelines; worth double-checking these resolve correctly at camera-ready.
- The number example in the introduction ("six hundred sixty-six thousand six hundred sixty-six") is vivid but a footnote on why this specific example was chosen (versus being cherry-picked for its repeated digits) would help.
- Table 1's "Qwen3-TTS-1.7B" row (0.0% count-error gap, 38.9% vs 98.9% exact-match) is used in-text as a striking illustrative case ("including the one whose median-error gap is zero, which still renders repeated items exactly 60.0 points less often") — worth flagging in the table itself (e.g., a footnote marker) rather than only in prose, for readability.

### Verdict

**Major revision** — the robustness program (multi-recogniser validation, penalty/decoding sweeps, specification curve, pre-registered CosyVoice-2 test) is genuinely strong and the core repetition-vs-control gap is likely real, but the paper's causal attribution to "periodicity" specifically is undercut by an unresolved OOD-naturalness confound, a control set that is itself periodic above k=8, and several of the mechanistic sub-claims (ordering vs. identity, state-vs-readout) rest on small, single-shot contrasts that shouldn't yet carry the weight the prose places on them.
