### Summary

The paper argues that autoregressive TTS models miscount long runs of a repeated phrase not because of exposure bias or a missing alignment constraint, but because softmax attention over k identical spans dilutes to weight Θ(1/k) (Lemma 1), making the decoder's per-repetition update approximately state-independent; if that update is a contraction (Assumption 2), a Lean-4/mathlib-verified theorem (Theorem 1) shows no Lipschitz readout — including the model's own stop head — can separate repetition counts beyond a horizon N*. Six AR TTS checkpoints across three families are evaluated on a repetition ladder (k up to 32, later extended post hoc to 128) against length-matched distinct-word controls, scored by a CTC recognizer chosen because Whisper is itself shown to be repetition-biased. Repeated items are undercounted (median error −8.3% pooled, 18.2% exact) while controls are essentially exact (94.3%), and the dissociation survives penalty and duration-conditioning ablations; count saturates only past k=32, one non-AR baseline (F5-TTS) also shows the effect while another (VITS) does not, and the theorem's own premise (contraction) fails two direct measurement attempts, with the dose-response prediction of Lemma 1 coming out sign-reversed. A single linear-probe test on one checkpoint is offered as the paper's one clean confirmation of the theorem's conclusion.

### Major concerns

1. **Issue** — The public code/data release is linked under a repository name that does not match the paper's subject, and none of the URLs, checkpoint hashes, or scoring-pipeline internals it is said to contain can be verified from the manuscript text alone.
   **Where** — Section 3, "Code, data, settings": `https://github.com/lab260ru/icassp_antispoofing`.
   **Why it matters** — The paper's central reproducibility claim is that "`build.sh` regenerates every number here." A repo named `icassp_antispoofing` for a paper about repetition-counting collapse in TTS is either a mislabeled/placeholder link, a generic lab monorepo that mixes unrelated projects (making it hard for a reader to isolate what's relevant), or a copy-paste error from a different submission — any of which weakens confidence that the linked artifact is the complete, correct one described. Since essentially every quantitative claim in the paper (the -8.3%, 18.2%/94.3%, the k=128 extension, the probe results) is asserted to be regenerable from this repo, an unverifiable or mismatched link undercuts the paper's strongest methodological asset.
   **What would address it** — Confirm the exact, permanent URL (ideally a tagged release with a DOI, e.g. via Zenodo) at camera-ready time, use a topic-matched repository name or a clearly labeled subdirectory, and state the release's contents explicitly in the paper (file manifest) rather than only in prose.

2. **Issue** — The procedure for converting a raw CTC transcript into the count ĉ used in every headline statistic is never specified in the main text, nor are the criteria for excluding the 342 "fillers-not-transcribed" items or the 19 "degenerate" generations.
   **Where** — Section 3, "Behavioural measurement" and the exclusion sentence ("Of 2052 panel generations we exclude 342 … 132 … and 19 degenerate, leaving 1559"); Section 4.2 repeats an analogous unstated "degenerate" criterion for the extension ladder.
   **Why it matters** — Whether ĉ is derived by exact string count, fuzzy alignment, edit-distance matching against the target word, or some acoustic-unit count, materially affects the error statistic that is the paper's headline number (median −8.3%, exact-match 18.2% vs 94.3%). Similarly, "degenerate" is doing real work (10-20 generations dropped per analysis) without a stated operational definition (e.g. a WER threshold, silence detection, looped-audio detector). Without these, a reader with only the released transcripts cannot reproduce the reported numbers, only re-derive them if they guess the same procedure the authors used.
   **What would address it** — State the scoring algorithm (even briefly, e.g. "we align the CTC transcript to the target token via X and count matches within edit distance Y") and the exact automated/manual rule used to flag "degenerate" in the main text or at minimum in a clearly indexed, self-contained supplement section, with the classifier or script referenced by name and released.

3. **Issue** — Nearly every non-trivial methodological detail (the dose-response test in §4.4, the effective-rank/capacity-gain measurement, the penalty-sweep configuration, the probe's training/evaluation protocol, and the post-hoc-decision audit trail) is deferred to supplementary sections (S5, S8, S10–S13, S15, S16) that are not part of, or available alongside, the reviewed text.
   **Where** — Throughout Sections 3–5 (e.g., "S10", "S11", "S12", "S13", "S15", "S16" citations).
   **Why it matters** — A paper whose main-text claims are this dependent on an appendix cannot be fully assessed, or reproduced, from the manuscript in isolation. This is particularly consequential for the theorem-confirming linear-probe result in §5, which is reduced in the main text to a single sentence ("on 12 items and one checkpoint") with the actual probe architecture, training data, and cross-validation protocol left entirely to S12 — yet this is presented as the paper's one piece of direct evidence for Theorem 1's conclusion.
   **What would address it** — For ICASSP's page budget this is a structural constraint, but the paper should at minimum state, inline, the two or three implementation choices that most affect the reader's ability to trust each headline number (probe class, feature dimensionality, train/test split, degenerate-generation detector), and ensure the supplement itself is released alongside the code so these can be checked ex post.

4. **Issue** — Checkpoints are identified only by family and parameter count (e.g., "Llasa-8B", "Qwen3-TTS-1.7B"), with no stated model revision, commit hash, or download date.
   **Where** — Section 3, "Models."
   **Why it matters** — All three families (Llasa, XTTS-v2, Qwen3-TTS) are actively maintained open-weight projects whose public checkpoints can be updated or replaced. Without a pinned revision, "regenerating every number" from the released seeds is only guaranteed to work at the moment of submission; a reader six months later re-running the pipeline against the then-current "Llasa-8B" weights may get a materially different decoder and hence different counting behavior, silently invalidating the claimed reproducibility.
   **What would address it** — Record and publish the exact HF Hub revision hash (or a local mirror/checksum) for every one of the six checkpoints, plus the two non-AR baselines, in the released repository.

5. **Issue** — Explicit sampling/decoding hyperparameters are given for the three autoregressive families but not for either non-autoregressive baseline (VITS, F5-TTS), even though the F5-TTS vs. VITS split is the paper's one piece of evidence against a purely-AR account of the effect.
   **Where** — Section 3, "Code, data, settings" (hyperparameter list) vs. Sections 4.3 (F5-TTS/VITS results) and 4.3's duration-conditioning experiment.
   **Why it matters** — Section 4.3 leans heavily on the F5-TTS/VITS dissociation to walk back the paper's own "architectural" framing ("we withdraw the architectural claim"), and the duration-supply experiment on F5-TTS ("supply the duration a correct rendering takes...") is offered as evidence separating a duration-estimation failure from the "severe end of the deficit." Reproducing either result requires knowing F5-TTS's NFE steps, CFG/guidance scale, and duration-predictor configuration, and VITS's noise/length-scale settings — none of which are stated.
   **What would address it** — Report the same level of hyperparameter detail for VITS and F5-TTS as for the AR families, in the main text or repo README.

6. **Issue** — The paper's one confirmatory test of Theorem 1(iv)'s conclusion is run on 12 items from a single checkpoint, and the post-hoc k=128 extension that motivates it covers only 4 of the 6 checkpoints, with one of those four (Qwen3-TTS-1.7B) showing no effect at all and left as an "unexplained exception."
   **Where** — Section 4.2 (extension ladder) and Section 5 ("The theorem's prediction, tested where it applies, on 12 items and one checkpoint: one clean observation, not a panel result").
   **Why it matters** — This is the only place in the paper where the theorem's distinctive prediction (a Lipschitz-readout wall, not just a saturating count) is tested directly, and the authors themselves label it "one clean observation, not a panel result." Readers skimming the abstract's "Its conclusion does survive one direct test" risk overweighting this into a general confirmation of Theorem 1, when it is, by the authors' own accounting, an n≈12/1 anecdote riding on a post-hoc extension whose saturation scale K̂ is explicitly *not* derived from a measured contraction factor q, and which one of four extended checkpoints contradicts outright.
   **What would address it** — Either extend the probe test to the other extended checkpoints (even partially) to see if the pattern replicates, or soften the abstract/discussion framing so "the conclusion survives one direct test" is not read as more than the single-checkpoint anecdote it is; explicitly report the probe's performance on Qwen3-TTS-1.7B (the exception case) as a targeted falsification attempt.

### Minor concerns

- Reference [1] (Wang et al., "Eliminating stability hallucinations...") is cited in the Introduction as documenting the counting/stability problem but is itself annotated as "Withdrawn 13 Feb 2026" — leaning on a withdrawn preprint, even for peripheral framing, is worth flagging or replacing with a non-retracted source.
- Figure 1 caption/axis text as rendered ("22 25", "26 27", "0 50") looks like garbled/OCR-damaged axis labels (likely log-scale tick marks); if this is a rendering artifact of the extraction rather than the source PDF, it should be checked before camera-ready, since Figure 1 carries most of the paper's evidentiary weight.
- The paper mixes two different summary statistics for the same headline claim (median error "−12.5% per checkpoint" vs. "−8.3% [−12.5, −6.2] pooling items") in the same sentence without a clear default; pick a primary number for the abstract and clearly subordinate the other.
- Companion self-citation [7] ("From dispersion to attraction...") is used to position this paper as one half of a matched pair of hallucination studies; this is disclosed but worth an explicit COI/independence note given the overlapping authorship.
- Abbreviations "S5/S8/S10/S11/S12/S13/S15/S16" are never expanded (presumably "Supplement §"); a one-time gloss would help readers unfamiliar with the venue's supplement convention.
- The 666,000,666 example in the opening sentence is memorable but its digit-repetition structure is not obviously the same phenomenon as the phrase-repetition ladder tested later (number phrases are described only as having "intrinsic digit-word repetition" in §3, without saying how many are in the 180-item set) — worth a sentence tying the anecdote to the actual stimuli count.

### Verdict

**Major revision** — the empirical program is unusually careful and honest about its own limits (failed premise measurements, a sign-reversed dose-response prediction, a withdrawn architectural claim, an n=12/1-checkpoint confirmatory test candidly labeled as such), but the paper's reproducibility claims outrun what the main text actually lets a reader verify: the scoring pipeline that produces every headline number, the exact model revisions, and the non-AR baselines' hyperparameters are all either unspecified or deferred to an inaccessible supplement, and the linked repository's name does not match the paper's subject.
